### Findings
1. **[blocking][spec] F3: in dark mode, a toast's description text is unreadable (contrast 1.56:1).** Sonner styles `[data-description]` with a hard-coded `color: #3f3f3f` (`styles.css:127-131`). Only `[data-sonner-theme='dark']` changes it (`:137`). With no `theme` prop, sonner's theme stays `'light'` (`index.tsx:615`), so the four token variables flip the toast background to `rgb(32, 31, 29)` while the description stays `rgb(63, 63, 63)`. That is 1.56:1, against WCAG AA's 4.5:1. Light mode is fine (10.53:1), and the title is fine in both themes (16.66 and 13.36). Evidence: [19](https://github.com/MaheshPulivarthi18/arxivlens-agents/blob/2ce982567db37293f4fe7fbd5e8c7cd6be8feadb/agents/reviews/FE-0b/evidence/19-r2-f3-toast-description.png?raw=true), [17 dark screenshot](https://github.com/MaheshPulivarthi18/arxivlens-agents/blob/2ce982567db37293f4fe7fbd5e8c7cd6be8feadb/agents/reviews/FE-0b/evidence/17-r2-ac6-smoke-dark.png?raw=true) (bottom-right toast). The design's sentence "toasts follow the theme with no `theme` prop" (§6, `sonner.jsx` row) is incomplete, and AC3 copies it, so this is also a spec gap. You can still fix it inside `sonner.jsx` without a `theme` prop. **Fix control** (scratch copy, not pushed): adding `toastOptions={{ classNames: { description: "!text-muted-foreground" } }}` gives 6.73:1 in light and 6.68:1 in dark ([19](https://github.com/MaheshPulivarthi18/arxivlens-agents/blob/2ce982567db37293f4fe7fbd5e8c7cd6be8feadb/agents/reviews/FE-0b/evidence/19-r2-f3-toast-description.png?raw=true), [19 control dark](https://github.com/MaheshPulivarthi18/arxivlens-agents/blob/2ce982567db37293f4fe7fbd5e8c7cd6be8feadb/agents/reviews/FE-0b/evidence/19-r2-f3-fix-control-dark.png?raw=true)). The `!` is needed because sonner's selector has specificity (0,3,0).
2. **[nit] N2: the PR body is stale.** It still says "159 lines" and describes the ScrollArea ring without the inset deviation. Refresh it with the rework (pm-lead rewrites it at stage 4 anyway).
3. **[nit][spec] N3, for FE-4: the ScrollArea viewport has no `tabindex`.** It is keyboard-reachable here only because Chromium (and Firefox) make scroll containers focusable when they have no focusable children. If FE-4 puts plain-text passages in a ScrollArea, it should pass `tabIndex={0}` (and an `aria-label`) on the caller side.
