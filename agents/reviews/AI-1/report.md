## PRD fit
This PR adds tests and changes no feature behaviour. It pins QA-3 (marker → paper/section/content/PDF link, tested via `TestAskAnswersWithValidatedCitations`), QA-4 (≥ 0.50 support labelling, including the documented fail-open gap that AI-2 owns), QA-5 (exact refusal text, no embedder call) and QA-6 (aux-section 0.70 cutoff), matching the Technical PRD §7.2 flowchart. The splitter fix helps "evidence first": a marker no longer gets verified against a sentence fragment that has lost its claim.

## Findings
1. [nit] The diff has 429 changed lines, over the 400 target (CI warns). About 18 are moved code. Not blocking: it is a target, not a gate.
2. [nit] The abbreviation list doesn't cover everything. `"U.S. data is used [1]."` still splits into `"U.S."` + `"data is used [1]."` ([07](```````````````````https://github.com/MaheshPulivarthi18/arxivlens-agents/blob/0e35400eab43e3a7e5efebf4e6c1211b6cdcf9fb/agents/reviews/AI-1/evidence/07-ac4-splitter-old-vs-new.png?raw=true)).``````````````````` Other common forms such as `Sec.`, `approx.`, `resp.` and `Tab.` are missing too. A real sentence ending in a listed abbreviation now merges with the next (`"…Smith et al. They report 90%."`). This trade-off is documented, and the current template can't trigger it because its sentences end in `[n].`. Worth revisiting when QA-8 brings LLM-written text.
3. [spec] AC2 says "`go test -cover`, paste number", but that command reports a package-wide figure (68.1% or 52.5%, depending on which files are compiled in) and CI doesn't print coverage at all. Future tickets should name the measurement: `-coverprofile` filtered to the file, as in `scripts/coverage.sh`. Better still, `make test-go` could print per-file coverage.
4. [spec] Follow-up for pm-lead (no ticket exists yet, as far as I can see). Under QA-5, `RerankScore == 0` (reranker down, or no rerank score) skips the 0.45 relevance cutoff, so `/v1/ask` fails open and answers from unranked hits. Also, `EarlyRefusalThreshold = 0.015` is declared but never used. This PR correctly pins both and doesn't change them. Deciding the right behaviour is a product/ADR question.

No blocking findings.
