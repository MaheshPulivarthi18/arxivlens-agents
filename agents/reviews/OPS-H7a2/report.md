## Design check
- Shape/Q2/Q3: `List` takes one start-time `Watermarks` snapshot and reads `[from, High)` per partition in ascending order. Errors are returned and never treated as end. The cursor is `P/O`. `--from` continues into later partitions from their `Low`. All of this matches. Q2 says an empty partition is "skipped without a fetch". `List` still calls `Read` on it, but `KafkaReader.Read` returns at `from >= until` before it creates a client (`kafka.go:153`), so no fetch happens. Acceptable.
- **Deviation:** `ListOptions` has a 4th field, `Snapshot map[int32]Watermark`. The design (`OPS-H7.md:46`) and the ticket Scope both say `ListOptions{Partition *int32; From Cursor; PageSize int}`. The reason holds up: without it, `--all`/`inspect` would re-snapshot on every page, which breaks Q2's "start-time watermarks". M10 shows the test pins it. It is internal API, not a shared contract (AGENTS.md §2). But it is recorded only in the ticket Notes and the PR body, not in the design file: 0 occurrences of `Snapshot`, and there is no "Build notes (a2a)" section ([09](`````````` https://github.com/MaheshPulivarthi18/arxivlens-agents/blob/b146cb790064b0865849e0e0eaccef22959e6c10/agents/reviews/OPS-H7a2/evidence/09-design-deviation.png?raw=true)). `````````` **Finding 3.** The `Page.Warnings`/`Page.Watermarks` fields aren't in the design either. They are the natural carriers for Q2/Q3 output, so record them in the same note.
