## Goal
Every `/v1/ask` calls three embedder-API endpoints: `/internal/embed`, `/internal/rerank` and `/internal/verify` (`services/embedder/api.py:230`, `:247`, `:213` at `11c4696`).
An on-demand ingest holds `_ingest_lock` (`api.py:288`, `:306`) for 30–80 s. AI-12b pinned that `/internal/embed` doesn't take that lock. Nothing pins the other two.
So a later change that wraps `/internal/rerank` (cross-encoder path or bi-encoder fallback) or `/internal/verify` in `with _ingest_lock:` would make every
answer wait behind an ingest, and all tests would stay green. This task adds those tests. It also stops a regressed test's ingest thread from outliving its test (AI-12b QA nit 1).

## Acceptance criteria
- [ ] AC1 (rerank, cross-encoder path): set `api.reranker_model` and `api.reranker_tokenizer` to non-None sentinels and monkeypatch
  `api.score_pairs` with a fake that records `api._ingest_lock.locked()` and returns `([0.5] * len(passages), {})` (`_format_stats`, `api.py:119`,
  accepts an empty dict). While an ingest is in progress (lock held, no `exit` in the
  fixture log yet), `api.rerank_endpoint(api.RerankRequest(query="q", passages=["a", "b"]))` returns `scores == [0.5, 0.5]`. At return, the
  lock is still held and the log has zero `exit` entries. The fake `score_pairs` was called once, with the sentinel tokenizer and model.
- [ ] AC2 (rerank, bi-encoder fallback): `api.reranker_model = None`, and `api.embedder` is a fake model whose `embed_texts(texts, is_query)`
  returns a `numpy` array of shape `(len(texts), 768)` and records `(texts, is_query, api._ingest_lock.locked())`. During an in-flight ingest,
  `rerank_endpoint` with two passages returns 2 finite float scores, and at return the lock is held with zero `exit`s. The fake recorded exactly
  `[(["q"], True, True), (["a", "b"], False, True)]`, which proves that the fallback path ran (not the cross-encoder) and ran under a held lock it did not take.
  Make `score_pairs` a fake that raises `AssertionError` in this test, so the wrong path fails loudly.
- [ ] AC3 (verify): set `api.nli_model`, `api.nli_tokenizer` and `api.nli_entail_idx` to sentinels. Monkeypatch `api.nli.verify_pairs` with a fake that
  records the lock state and returns `([0.9], {})`. During an in-flight ingest, `api.verify_endpoint(api.VerifyRequest(pairs=[api.VerifyPair(claim="c", passage="p")]))`
  returns `scores == [0.9]` and `model == api.NLI_MODEL`, with the lock held and zero `exit`s at return. The fake was called once, with `[("c", "p")]`.
- [ ] AC4 (bounded, no hang, no leak): every endpoint call runs in its own thread with a bounded `join`. A regressed endpoint that takes
  `_ingest_lock` must make the test **fail** (lock no longer held / an `exit` already logged at return), not hang. The ingest thread is joined
  before the test returns **whether or not an assert failed**, e.g. in a `try/finally` or a fixture finalizer, with a timeout longer than the
  ingest's total sleep. After joining, each test asserts that the ingest returned `status == "success"`.
- [ ] AC5 (mutants, one per case; QA or developer runs them, evidence file): each mutant below makes **its own** test fail, with all other
  tests in the file still passing, and no run takes longer than 30 s:
  (m1) wrap the cross-encoder branch of `rerank_endpoint` in `with _ingest_lock:`;
  (m2) wrap only the `elif embedder is not None:` fallback branch in `with _ingest_lock:`;
  (m3) wrap the `try:` body of `verify_endpoint` in `with _ingest_lock:`;
  (m4) swap the order of the two `rerank_endpoint` branches (fallback checked first), which AC1/AC2 must catch through their path asserts.
  Mutants are applied to a scratch copy and never committed.
- [ ] AC6: `ruff check --isolated --select E,F,W --line-length 130 tests/test_verify.py` has no findings on added lines.
- [ ] AC7: CI on the PR is green: jobs `Python M0 unit tests` (step `make test-py-ml` lists the new tests as passed), `Go (vet, gofmt, test, build)`
  and `Frontend (lint, test, build)`. `git diff origin/main --name-only` is exactly `tests/test_verify.py`.
- [ ] Docs: none. No behaviour or command changes. `CONTRIBUTING.md:25` already lists `tests/test_verify.py` under `make test-py-ml`.
