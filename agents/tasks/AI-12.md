## Goal
Every `POST /internal/ingest` builds a new `ProcessorWorker()` (MinIO client, parser, `TokenChunker` tokenizer, a new Kafka producer)
and a new `EmbedderWorker()`, whose constructor loads a second copy of `BAAI/bge-base-en-v1.5` from disk
(`services/embedder/api.py:286,311`, `services/embedder/worker.py:33`). That adds model-load time to every on-demand ingest, holds a
second model copy in memory while it runs, and leaks a Kafka producer per call. Build each worker once per process and make the
embedder worker use the model the API already loaded at startup.

## Scope
- Files expected to change (and only these):
  - `services/embedder/worker.py`: `EmbedderWorker.__init__(self, embedder=None)`; uses the given embedder if not None, else builds
    `BGEEmbedder(model_name=config.embedding_model)` as today. The Kafka worker entry point (`main`/consumer path) is unchanged and still
    calls `EmbedderWorker()`.
  - `services/embedder/api.py`: module-level lazy singletons for the two ingest workers, built on first use under a `threading.Lock`
    (so two concurrent first requests build each worker once; building them inside the pipeline lock below is fine, one lock may do both). `EmbedderWorker(embedder=embedder)` gets the startup-loaded
    global `embedder`; if it is `None` (startup failed) it falls back to `EmbedderWorker()`. A failed construction is **not** cached (the
    next request retries). The ingest pipeline (process + embed + count queries) runs under one module-level lock, because
    `TokenChunker`'s tokenizer and the workers are not documented thread-safe; ingest is on-demand, one paper per call, and the Go caller's
    timeout is 5 min (`internal/config/config.go` `DefaultIngestTimeout`). Add `/internal/ingest` to the module docstring's endpoint list.
  - `tests/test_verify.py`: new tests for the above (this file already holds the embedder-API endpoint tests and is in `make test-py`;
    `Makefile` is backend-owned, so no new test file).
- Out of scope: `services/processor/worker.py` (backend-owned; it is only *instantiated* once, not changed), honouring client
  cancellation / `INGEST_TIMEOUT` end to end (backend half of the same Backlog line, stays in Backlog), the duplicated paper-id query and
  the hard-coded `occurred_at` in the endpoint (separate nits, do not touch), `Makefile`, `README.md`.

## Acceptance criteria
- [ ] AC1 (reuse): with `api.ProcessorWorker` / `api.EmbedderWorker` monkeypatched to counting fakes and `psycopg.connect` patched to a fake
  connection, two sequential `ingest_paper_endpoint(...)` calls construct each worker class **exactly once** and call each fake's
  `process_message` twice. Mutation: building the workers inside the endpoint again (today's code) makes the test fail.
- [ ] AC2 (shared model): with `api.embedder` set to a sentinel object, the fake `EmbedderWorker` is constructed with `embedder=<sentinel>`.
  With `api.embedder = None`, it is constructed with no embedder (or `embedder=None`). Mutation: passing nothing in the first case fails it.
- [ ] AC3 (worker uses the injected model): with `services.embedder.worker.BGEEmbedder` monkeypatched to raise, `EmbedderWorker(embedder=x)`
  succeeds and `.embedder is x`; `EmbedderWorker()` still calls `BGEEmbedder(model_name=config.embedding_model)` (assert the fake got that
  `model_name`).
- [ ] AC4 (concurrency): two threads calling the endpoint at once, with a fake `ProcessorWorker` constructor that sleeps ~0.2 s, still
  construct each worker once, and their `process_message` calls don't overlap (the fake records enter/exit and asserts no interleaving).
  Mutation: removing the lock (every lock, if there are two) makes the count assertion **and** the no-overlap assertion fail; paste the
  result of the 20-run loop in Verification for both the real code (all pass) and the mutant.
- [ ] AC5 (no poisoned cache): a fake `ProcessorWorker` whose constructor raises on the first call → first request gets HTTP 500 (the
  endpoint's existing `HTTPException`), second request constructs it again and succeeds.
- [ ] AC6 (full stack): `stack.yml` runs on the PR (its `pull_request` paths include `services/embedder/**`). Its step
  `Seed the M3/M4 fixture (on-demand ingest of 2608.20331)` prints an `ingest.json` with `"status":"success"` and `chunks` and
  `embeddings` > 0, and the run is green apart from the documented known failure F1 (if still present). Quote the run ID and the
  `ingest.json` line from the job log.
- [ ] AC7: CI `ci.yml` job `Python M0 unit tests`, step `make test-py`, passes; the new tests appear in it (the step uses `pytest -q`, so
  also run `python3 -m pytest -rA tests/test_verify.py` locally or quote the counts). `ruff` clean on added lines. Diff only touches the
