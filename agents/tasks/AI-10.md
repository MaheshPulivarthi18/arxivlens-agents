## Goal
Bring the CPU rerank of the ADR-0010 pool down far enough that the three F1 tests pass under M3's unchanged 10 s timeout,
using only the options ADR-0015 accepts. Measure the quality cost on the `evals/` corpus and adopt a new default only under
ADR-0015's rule.

## Scope (provisional: final once ADR-0015 is decided; the design fixes the details)
- `services/embedder/api.py`: `RERANK_QUANTIZE` (`none` | `int8`) and `RERANK_MAX_LENGTH` (int, default 512) env settings, read at
  `load_models`, logged at start-up and added to the existing per-request timing line. Defaults stay unchanged until the
  measurement picks one.
- Measurement: each candidate config from ADR-0015, on one seeded corpus and one commit, gives rerank p50/max, `/v1/ask` p95,
  the F1 result, Recall@5, MRR, NDCG@5 and top-5 overlap against fp32-512. The design picks the vehicle (e.g. one
  `workflow_dispatch` of `eval.yml` with the embedder restarted per config, within the job's budget, or `stack.yml` plus
  `scripts/evaluate_retrieval.py`). Any workflow change is a backend follow-up, not this ticket.
- `tests/test_m0.py`: mocked tests that the env settings reach the tokenizer call (`max_length`) and the quantize call.
- Out of scope: pool size (ADR-0010), a different model, ONNX, any timeout or threshold change, dropping the F1 step (backend
  follow-up after this merges).

## Acceptance criteria (provisional)

- [ ] AC2: The chosen default follows ADR-0015's adoption rule exactly (order and tolerance as accepted). If no config

- [ ] AC5: README Environment rows for both env vars; `evals/BASELINE.md` before/after (EVAL-4 owner coordinates).
